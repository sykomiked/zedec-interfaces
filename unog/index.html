The account model

Storage keys are derived, not enumerable:

account record : 0x00 ‖ sha256("A" ‖ account_id)
balance record : sha256("B" ‖ account_id ‖ asset_id)
NEAR → L2 map : sha256("near-account:" ‖ accountId)

There is no prefix scan. A balance key hashes its preimage, so the account set is opaque while every individual balance stays provable.

The consequence everyone hits: minting credits an internal account, not a wallet. A second transaction (export) moves it to a NEP-141 balance.

The four-valued state machine

A verdict is TRUE, FALSE, BOTH or NEITHER. Only TRUE settles. When two valid, conflicting attestations arrive, the system records BOTH and releases nothing rather than silently picking a winner.

A last-writer-wins chain resolves the conflict and destroys the information that the community disagreed. This one keeps it.
