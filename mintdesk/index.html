Settlement is two steps, not one. A UI must show the request state, not just the transaction hash — the burn and the payout are separate events.

The bug that made this contract necessary to get right

The sealed core calls ft_on_transfer with snake_case arguments. A contract built with near-sdk's #[near] macro renames them to camelCase, the deserialiser fails, and the transfer is silently refunded with no error.

A silent refund looks identical to a successful transfer from the user's side — the worst possible failure mode for a money-handling contract. Both the desk and the bridge use #[near_bindgen] for exactly this reason.
